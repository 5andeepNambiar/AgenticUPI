End-to-End Test Flow

1

Open User Dashboard

Visit http://localhost:4200 to see the Angular mandate manager.

You'll see one active mandate: agent_demo_1 (Demo AI Travel Agent) authorized for ₹1,000/day.

2

Trigger a Payment from Python SDK

Call the Python Agent SDK endpoint to simulate an LLM making a payment decision:

curl -X POST http://localhost:8000/agent/execute-payment \ -H "Content-Type: application/json" \ -d '{ "payer_vpa": "user@upi", "payee_vpa": "merchant@hdfc", "amount_paise": 50000, "category": "FOOD", "agent_context": "Paid for lunch delivery" }'

The Python client will sign this payload with raw-byte HMAC and forward it to the Java backend.

3

Java Backend Validates & Executes

The backend will:

  • Verify HMAC signature (raw-byte match)
  • Check replay window (5 min clock skew)
  • Lock user's account balance (pessimistic)
  • Verify mandate status & daily velocity
  • Create transaction + double-entry ledger
  • Fire Outbox event to Kafka
{ "txn_id": "txn_abc123xyz", "status": "LEDGER_RESERVED" }
4

View Mandate Revocation (Kill-Switch)

Go back to http://localhost:4200 and click "🚨 Revoke Access" on the mandate card.

This triggers a pessimistic database update: the mandate status changes to REVOKED on the backend first, then the UI refreshes to show the change.

Future payments from this agent will be rejected with MANDATE_REVOKED.

5

Inspect Database & Cache State

Query the MariaDB to see the transaction ledger:

docker exec -it agenticupi_db mysql -u api_user -p agenticupi SELECT * FROM transactions LIMIT 10; SELECT * FROM ledger_entries LIMIT 10;

Redis velocity/idempotency cache expires in 48 hours. Inspect via docker exec -it agenticupi_redis redis-cli KEYS "idemp:*"

🎯 Interview Signal: Why This Architecture Matters

This system demonstrates the exact patterns asked about at Principal/Staff level in fintech:

  • Raw-Byte HMAC: Eliminates JSON canonicalization vulnerabilities across Python ↔ Java integration.
  • Idempotency Lifecycle: UUID generated outside retry loops prevents accidental double-debits on timeouts.
  • Two-Phase Velocity: Redis holds pending reservation; DB commit finalizes it via post-commit hooks. If DB rollbacks, Redis is cleared. No lost quota.
  • Pessimistic Kill-Switches: Mandate revocation updates DB first, then caches tombstone. Fail-closed: if cache is down, DB blocks the payment anyway.
  • SKIP LOCKED Outbox: Multiple pods claim rows without contention. Kafka I/O happens outside DB locks. Horizontal scale without lock timeouts.
  • Declarative UI: Angular RxJS streams + OnPush change detection. No manual subscription management or memory leaks.
